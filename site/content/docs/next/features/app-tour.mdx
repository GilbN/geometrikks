description: What each page in the GeoMetrikks web UI shows, in the order the navigation lists them.
---

The sidebar lists the pages in this order. On a phone the tab bar holds Overview, Map, Access Logs and either Security or Analytics, and More holds the rest. Security only appears once CrowdSec is set up or AbuseIPDB reporting is on, and then takes the fourth place in the tab bar. Without either, Analytics takes it.

The top bar shows the current page name. Hovering it on desktop or tapping it on a phone shows the page's description. On desktop, the bar also holds the time range button, which names the range and the dates or times it covers, and a split button for refresh and auto refresh. Pages that don't use the time range, Security and Settings, show no range or refresh controls. A search field in the desktop top bar opens [search and commands](./keyboard-shortcuts.mdx#search-and-commands), shrinking to an icon button on narrow windows. On a phone, a search button in the header opens it as a full-screen sheet.

Most pages read the time range in the top bar, and Access Logs, Geo Logs, Analytics and the map keep their filters in the page URL, so a filtered view is a link you can share. Wherever an IP address appears in a table, the button after it opens the IP actions menu. The [IP inspector](./ip-inspector.mdx) page covers what it offers.

## Overview

Traffic, status codes and response times for the selected range, each figure with its trend against the previous range of the same length. The page has four sections: Traffic Overview, Traffic Origin, HTTP Status Codes, and Performance & Bandwidth. The Charts switch at the end of the Traffic Overview heading row draws a small chart under each figure, and the Buckets menu beside it sets Auto, Hourly or Daily buckets for every page with charts. Auto picks hourly buckets for ranges up to and including 7 days, even when a week gains an hour to daylight saving, and daily buckets above that, so the default Last 7 days range shows hourly charts. On a phone, both controls sit in the time range drawer.

<Screenshot scene="dashboard" />

Traffic Origin splits the range's traffic by the network it came from:

- **Spamhaus DROP** is the share of requests from networks on Spamhaus's ASN-DROP list, with the count of listed ASNs that sent them. It appears once the DROP lists have downloaded. See [Spamhaus DROP lists](./drop-lists.mdx).
- **Hosting Traffic** is the share from networks on a bundled community list of hosting, VPN and datacenter operators. Settings > About has the list.
- **Top Network** is the AS that sent the most requests.

Both shares are of classified requests, the ones with ASN data. When part of the range has none, for example history from before ASN lookups or with `GEOIP_ASN_ENABLED=false`, the subtitle says how much of the range the share covers. With no ASN data in the range the section doesn't show at all.

## Map

The live world map, with heatmap, markers and a banned view, live routes to each server, and the live rail. See [Map](./map.mdx).

## Access Logs

Every stored request, newest first, in two tabs: History and Live tail.

<Screenshot scene="access-logs" />

History is the searchable table. On desktop, one filter bar replaces the filter panel and table card header, so the table fills the remaining height of the window and keeps the pager and row count on screen. From left to right, the bar holds the History and Live tail tabs, the search field (which matches the URL, referrer and user agent), one chip per active filter, and a `+ Filter` button that shortens to `+` once a chip is present. Chips wrap to a second line when the bar fills up, so all stay visible. On the right sit Clear (shown when two or more filters are set, counting search), the [Muted IPs](./muted-ips.mdx) button when your list has entries, and the View menu (or the sort button on a narrow window).

The Filter menu lists IP address, Host, Server, Method, Status, Source format, Country, City and ASN. Picking a field puts a chip in the bar and opens its picker. List fields use a searchable checklist where each tick filters the table at once. IP address takes typed addresses and CIDR ranges such as `198.51.100.0/24` or `2001:db8:1:2::/64`. Press Enter to add each value, and use the remove button beside a listed value to drop it. The IP filters on Geo Logs, Analytics and Debug Logs accept CIDR ranges too. A range must start on its network address. Click any chip to reopen its picker, or click its `x` to remove that filter. Filters set from the command palette, `F` on a row, a row's IP actions menu or a shared link appear as chips too.

IP address, Host, Server and ASN have an `is / is not` switch in their picker. An `is not` chip is red with a ban icon. A field can hold an `is` chip and an `is not` chip at the same time, and switching a chip moves its values to the other side. Host and Server `is not` pick from the same list as `is`. Typing in the Filter menu's search field matches field names and also finds values by name across countries, cities, hosts, servers and networks (ASN), busiest first, with request counts. Pressing Enter or clicking a match sets that value as an `is` filter. A city match adds the city only.

Each field in the Filter menu has a pin button. A pinned field stays in the bar as a button with a chevron, so setting it takes one click. With a value it looks like any other chip, and its `x` clears the value and leaves the button. Pins are kept per browser and per page, and a new install has none. At the bottom of the Filter menu sit two switches. Hide my IP shows your current address, looks it up again on each use, and shows `Needs APP_TRUSTED_PROXIES` when the app sits behind an untrusted proxy. Hide muted IPs shows the entry count and turns off while an IP `is` filter is set. On a phone, the filters sit in a drawer split into Show only and Exclude, with the Exclude your IP button and the table header. Click a row for the full record.

On desktop Access Logs and Debug Logs, the View menu sits at the right end of the filter bar. On Geo Logs it stays in the table header, and Settings > Logs has one with only Rows and Time. Rows switches between Compact and Comfortable, defaulting to Compact with a mouse and Comfortable on a touch screen, and each table remembers its choice in the browser. On Access Logs, Geo Logs and Debug Logs, Columns defaults to Combined while Separate gives each field its own column: Access Logs merges Request, Client and Location; Geo Logs merges Location, Client and Coordinates; Debug Logs merges Result, Request and Client. Clicking a combined header sorts by its main field: path for Access Logs Request, city for Geo Logs Location, latitude for Coordinates, malformed for Result, and status for Debug Logs Request. The arrow beside the header picks the column's other visible sortable fields, so on Debug Logs Request it appears when both Status and Host are visible. Time defaults to 24-hour, such as `Nov 14 16:41:40`, with the browser's own format as the other choice, and one setting covers all the log tables and the live tail; on a phone it is in the sort drawer. The Visible fields submenu of View picks which fields appear; Bytes and Req time show by default, except on a phone, and the list adds upstream response time, HTTP version, remote user, user agent, server, source format, ASN and AS organization.

<Screenshot scene="filter-drawer" />

The IP actions menu on each row can also filter by the row's IP, host, server, country or ASN, and exclude its IP, host, server or ASN.

### Live tail

Live tail shows new requests as your proxy logs them. It keeps the most recent few hundred rows and pauses while the pointer is over the list. The pause button works on every device, and on a touch screen it is the only way to pause. Requests that arrive while it is paused wait in a buffer and appear when you resume. The History filters don't apply to it.

## Geo Logs

Traffic grouped by location and IP: where requests come from, how that changes over time, and which clients come back. The page has a map preview, cards for total events, unique IPs, countries and cities, an event chart, Top IPs, and Top locations with Countries, Cities and ASNs tabs. On desktop, the event chart's Hourly or Daily label opens the bucket choice for all charts. The ASNs tab has an abuse report button on each row; see [Abuse reports](./abuse-reports.mdx). The table below sits under the map and charts, keeps its header and View menu, and lists one row per location and IP.

On desktop, Geo Logs uses the same filter bar as [Access Logs](#access-logs), with no search field, so pressing `/` opens the Filter menu. The menu lists IP address (`is / is not`), Country, City, Server and ASN (`is / is not`), plus the Hide my IP and Hide muted IPs switches. Value search finds countries, cities, servers and networks by name, ranked by access-log request counts. The [Muted IPs](./muted-ips.mdx) button and the Charts switch sit at the right end of the bar.

<Screenshot scene="geo-logs" />

## Debug Logs

Debug Logs holds the lines the parser could not read and the requests it flags as malformed: a line that doesn't match the log format, a TLS handshake or SSH probe sent to an HTTP port, or a request with no valid HTTP method. Click a row for the raw line and, when there is one, the access-log row it belongs to. This is where to look when a log file produces no events.

On desktop, one filter bar replaces the filter panel and table header, as on [Access Logs](#access-logs). The rows fill the height left under the stat cards, so the pager and row count stay on screen, and the View menu sits at the right end of the bar. The bar starts with the "Raw line or parse error" search field, which `/` focuses. The Filter menu lists IP address, Lines, Country and City, and its value search finds countries and cities by name. IP address holds one address or CIDR range at a time with no `is not`, and entering a new one replaces it. Lines picks Malformed or Well-formed one at a time, and clearing it shows all lines. Debug Logs has no Hide my IP or Muted IPs controls.

With `LOGPARSER_STORE_DEBUG_LINES=true` the parser stores every line here as well, parsed or not. That grows the database by a row per request, so turn it on only while you chase a parsing problem.

## Analytics

Charts and top lists for the range, all following one filter set: IP address (`is / is not`), Host (`is / is not`), Country, City and ASN (`is / is not`), plus [Muted IPs](./muted-ips.mdx) when your list has entries. On desktop, the page uses the same filter bar as [Access Logs](#access-logs), with value search across countries, cities, hosts and networks by name, Hide muted IPs in the Filter menu and the Muted IPs button at the right end of the bar. The bar has no search field, so `/` opens the Filter menu. Analytics has no Hide my IP switch, and the charts keep normal page scroll. Both Host `is` and `is not` pick from the hosts the server has logged and match the logged Host value exactly. Excluding a host keeps requests that have no host.

- **Traffic** has three charts. Requests sits across the top, stacked by 2xx, 3xx, 4xx and 5xx status classes, and Bandwidth and Request latency sit side by side below it on desktop. On a phone, the three stack. Each chart's options menu sets its view and scale. Requests offers Stacked bars, the default, along with Stacked area, Share of responses and Error rate. When the range has requests outside 2xx to 5xx, the stacked views add an "Other statuses" segment and legend entry for them: 1xx such as WebSocket `101` upgrades, status 0 when a connection closed before any response, and other codes an import carried. Share of responses counts only 2xx to 5xx, while Error rate divides 4xx plus 5xx by all requests, so Other statuses count in its total. Bandwidth offers Area, the default, or Bars. Request latency offers Percentile band, the default, or Lines. Every chart defaults to "Linear, clip spikes", with "Linear, full range" and "Log" in the same menu. When the axis clips a spike, the header shows a "y-axis clipped at" note. With "Log", the stacked views draw as lines. A scale you pick stays saved, except that a Log scale saved by an earlier version goes back to "Linear, clip spikes" once, because older versions saved Log even when only the view changed. On desktop, each chart's Hourly or Daily label opens the bucket choice for all charts.

  Each chart shows its numbers in its header. At rest, the header shows totals for the range. When hourly data does not reach back to the start of the range because older hours have expired, the Requests and Bandwidth totals say "since" and the first day they cover, such as "since Sep 28". Request latency shows its legend labels only, since percentiles don't add up. The three charts share one cursor. Hovering a bucket on any chart marks it on all three and shows its values and time in all three headers. On a phone, hold a finger on a chart or drag sideways to do the same. A vertical swipe still scrolls the page, and phones have no drag to zoom. With the keyboard, Tab focuses a chart, Left and Right arrows step one bucket (the first arrow press marks the latest), Home and End jump to the first and last, and Escape or leaving the chart clears the selection. Each step updates the headers, and a screen reader reads the bucket out on keyboard steps only, not on mouse hover. On desktop, drag across a chart with the mouse to select hours. A shaded band labels the selection, such as "Nov 23, 12:00 AM to Nov 23, 10:00 AM · 10 hours". The headers total those hours as you drag, while Request latency shows labels only. Releasing zooms the page to those hours as a custom range in the top bar's range button, and the top lists follow it. A drag shorter than three hours does nothing. A drag over time whose detailed data has expired also does nothing, and the label over the drag says so: the zoom reads the hourly rollup (`ANALYTICS_HOURLY_RETENTION_DAYS`, 60 days by default) or, with a filter or Muted IPs on, raw access log rows (`ANALYTICS_RAW_RETENTION_DAYS`, 180 days by default). A zoom longer than 30 days without filters reads the daily rollup, which never expires, so it always works. Escape cancels a drag. A "Zoom out" button at the right end of the Traffic section line goes back to the range you zoomed from and names it, for example "Zoom out to Last 7 days". Zooming again stacks, so Zoom out steps back one zoom at a time. Changing the range any other way removes the button. On an hourly chart, day labels sit at midnight. Ranges of two days or less label every second or third hour and show the date at midnight. Hours with no traffic draw as empty buckets instead of being skipped.
- **Top Lists** has Top IPs, Top Countries / Cities, Top URLs with one row per host and path, and Top user agents. Top IPs shows how many unique IPs the filtered view covers in its header, counting IPs beyond the ones listed. Top Countries counts each country's errors, the requests with status 400 or higher. Each Top URLs row that has a host has a menu that filters by that host or excludes it. When you pick two or more hosts in the Host filter, Top URLs adds up each path across those hosts and drops its Host column. Excluding hosts never merges paths.
- **Traffic Origin** has the hosting and DROP split and Top ASNs. Each Top ASNs row has an abuse report button.

Request latency and the other response-time figures leave out status 101 and status 0. Under 101, nginx and Traefik log a WebSocket's whole connection time, and 0 means the connection ended before any response, so neither time is a response time. Those rows stay in Access Logs with the time the proxy logged.

## Security

CrowdSec decisions and alerts sit next to your own traffic, so you see who is banned and whether they are still sending requests. Stat cards sit at the top, and below them the page shows one table at a time in the Decisions, Alerts, DROP and Reports tabs. Alerts needs CrowdSec machine credentials, and DROP appears once the DROP lists have downloaded. Reports lists what GeoMetrikks has sent to AbuseIPDB and appears with AbuseIPDB reporting on. The open tab is in the URL, so a reload or a shared link keeps it.

<Screenshot scene="security" />

With AbuseIPDB reporting on and CrowdSec not set up, the page shows only Reports. With neither, it says how to connect CrowdSec. [CrowdSec](./crowdsec.mdx#the-security-page) covers the setup, the ban actions and each tab. The DROP tab is described under [Spamhaus DROP lists](./drop-lists.mdx#the-drop-networks-card), and Reports under [AbuseIPDB](./abuseipdb.mdx#the-reports-tab).

## Settings

### Status

Status shows the health of the whole app on one page. On desktop, one card starts with the verdict: Healthy, Degraded, Attention or Unreachable. Beside it are the uptime, the time of the last check and a Check now button, which asks the server for every component's state at once. The page also refreshes on its own. Below it sits one row per component: Ingestion, Database, GeoIP, CrowdSec, Scheduler, Live feed, Authentication, then Agents once agents write to the database, Server locations once a server has a location, and Recent errors.

Each row shows its state, a short summary and what changes next, such as the next refresh time. Ingestion starts open. Click a row, or press Enter or Space on it, to open or close its counters and tables. A row with a problem turns amber or red, moves to the top and opens by itself; if you close it, it stays closed while the problem lasts. Recent errors moves up and turns amber when the app log has recent errors, without opening by itself or changing the verdict. Authentication does the same when built-in login is turned off with `APP_AUTH_DISABLED=true`. Advisories above the card say when something needs attention, such as a missing ASN database or a server whose location could not be detected. On a phone, the page shows a verdict, the problems and a tile per component that opens a drawer.

<Screenshot scene="status" />

### Agents

Every instance that writes to this database, the full instance first, with its version, server names, recent line counts and last check-in. An agent that stops checking in is flagged. See [Settings > Agents](../sources/multiple-sources.mdx#settings--agents).

### Environment

The settings the app resolved at startup, with the ones your environment overrides marked. Secret values stay hidden. The [configuration reference](../reference/configuration.mdx) explains each one.

### API keys

Keys for scripts, monitors and dashboards. A key is Read or Read/write, and a Read key gets a 403 on anything that changes data. Browser logins don't use keys. [API keys](./authentication/api-keys.mdx) covers creating and revoking them.

### Scheduler

The background jobs, such as the GeoLite2 refresh, the server location refresh, the DROP lists refresh and the AbuseIPDB blacklist refresh, with their recent runs and next run. Run now starts a job straight away. When a job fails, an advisory names it until a run of that job succeeds. A job that runs more often than every 10 minutes raises it only after 10 minutes of failed runs.

### Logs

The app's own log in three tabs: System log, Login log, and Downloads for the raw log files. The system log updates live and filters by level, component and text.

### Appearance

The color scheme and theme for this browser. There are eight themes, Aurora, Moss, Forge, Night, Glacier, Dusk, Lyng and Storm, each with a light and a dark palette. Appearance also holds the switch for single-key [keyboard shortcuts](./keyboard-shortcuts.mdx).

<Screenshot scene="settings" />

### Changelog

What changed in each release, and which one this install runs. A dot on the Changelog entry, and on Settings in the sidebar, marks changes you haven't read yet.

### About

About shows the running version and its uptime, then the runtime, the database, the GeoIP databases with the hosting network list, the DROP lists, and the AbuseIPDB blacklist when it is on. With `APP_UPDATE_CHECK=true`, the default, the app asks GitHub every 12 hours whether a newer release exists. When one does, About shows it next to the running version. Until you open About, a dot sits next to the version number at the foot of the sidebar and on the About entry in Settings. Set `APP_UPDATE_CHECK=false` for an install that should not contact GitHub; the app then never shows a newer release.
